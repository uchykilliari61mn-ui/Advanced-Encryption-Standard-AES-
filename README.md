# AES — реалізація режиму CTR (Counter) на C#

Навчальна реалізація симетричного шифрування **AES у режимі CTR** із зашифруванням
та розшифруванням. На відміну від прикладу зі статті (режим **CBC**), тут сам режим
побудований вручну — AES використовується лише як блочний шифр, а логіка CTR
реалізована в коді.

## Чим CTR відрізняється від CBC

| | CBC | CTR |
|---|---|---|
| Як працює | кожен блок XOR-иться з попереднім зашифрованим блоком | генерується потік ключа з лічильника, яким XOR-иться текст |
| Доповнення (padding) | потрібне (дані мають бути кратні 16 байтам) | **не потрібне** |
| Розпаралелювання | послідовне | блоки можна шифрувати **паралельно** |
| Зашифрування / розшифрування | різні операції | **однакова** операція |

## Принцип роботи CTR

```
keystream_i = AES_Encrypt(counter_i)      // лічильник шифрується AES-ом
cipher_i    = plain_i  XOR keystream_i     // зашифрування
plain_i     = cipher_i XOR keystream_i     // розшифрування (та сама дія)
```

Лічильник стартує зі значення `IV` і збільшується на 1 для кожного наступного блоку.
Оскільки `A XOR B XOR B = A`, розшифрування — це той самий процес, що й зашифрування.

## Структура

- `AesCtrCipher.cs` — реалізація режиму CTR (`Encrypt` / `Decrypt`)
- `Program.cs` — демонстрація: шифрує рядок і розшифровує його назад
- `AesCtr.csproj` — проєкт .NET 6

## Запуск

```bash
dotnet run
```

Очікуваний результат: текст шифрується в «сміття» (hex), а потім успішно
відновлюється до вихідного рядка. Для демонстрації взято повідомлення, довжина
якого **не кратна 16 байтам**, щоб показати, що в CTR доповнення не потрібне.

## Важливо (безпека)

Ключ та IV у `Program.cs` захардкоджені лише для наочності. У реальних застосунках:

- IV (nonce) **ніколи не можна повторювати** з тим самим ключем — інакше потік ключа
  повторюється і шифр ламається;
- ключ має генеруватися з надійного джерела випадковості;
- CTR не забезпечує цілісності — на практиці його поєднують із MAC (наприклад, AES-GCM).
